# KMP Structure

Use one `:composeApp` KMP module with Compose Multiplatform, SQLDelight, Coroutines/Flow and Koin Annotations generated by KSP. Do not introduce shared/androidApp or feature Gradle modules.

## Source Sets

- commonMain: shared entry, domain, data, presentation and DI.
- androidMain: Android integration and actual platform providers.
- iosMain: Compose host integration and actual platform providers.
- commonTest: deterministic domain and feature behavior tests.
- androidUnitTest: real JVM-backed SQLDelight and Android checks.
- iosApp: native lifecycle, assets, signing, plist and framework host.

## Packages

Root: `goods.pocket.app`.

```text
App.kt
di/
domain/collection/ event/ settings/ dashboard/ service/
data/local/ repository/ runtime/ di/
presentation/shell/ navigation/ designsystem/ i18n/
presentation/home/ collection/ events/ my/ settings/
```

Dependencies are presentation -> domain and data -> domain. DI composes implementations. Domain has no Compose, SQLDelight, Koin, platform or cloud SDK types/annotations.

Preserve DatabaseDriverFactory and PlatformDataModule expect/actual boundaries. DB opening and I/O use an injected data dispatcher. Initialization failure is recoverable without deleting the database.

Tab state belongs to the host session; editor state belongs to its overlay. Each scope has an owner that cancels it. Keep KOIN_CONFIG_CHECK enabled; no AppContainer or manual service locator. Add remote implementations only after choosing their concrete requirements.
